# AgencyOS Being Custom

Purpose:

```text
Create a customized AI Being from the AgencyOS Being Core anatomy.
```

Product ladder:

```text
agencyos-solo = one agency
agencyos-pro = multi-agency work operating system
agencyos-being-core = foundational AI Being anatomy
agencyos-being-custom = generated/customized AI Being instance
```

This folder is not a raw merge of projects.

It is an anatomy map.

```text
Do not dump folders in.
Translate source material into anatomy.
```

## Core Anatomy

```text
Existence = why it is
Presence = how it attends
Intelligence = how it thinks
Skeleton = how it is structured
Body = how it runs and acts
Memory = how it continues
Governance = how it stays trustworthy
Skills = what it can learn to do
Personality = how it expresses itself
Behavioral Spectrums = how it adjusts behavior under tension
Portfolio = what it has created
Personal = private, user-approved context
History = provenance, outside the active self
```

## Source Relationship

```text
AgencyOS Pro provides Skeleton, Body, Skills, Portfolio, and Governance.
InnerLight provides Presence, Intelligence, Personality, Memory, and Governance.
Personal material enters only with approval.
History remains separate provenance.
```

## Custom Instance Rule

```text
Being Core is the template.
Being Custom is the generated instance.
```

Customize through:

```text
Skills = installed agent prompts and capability prompts
Personality = generated expression from role, domain, audience, and user preference
Behavioral Spectrums = adjustable operating tendencies selected for this being
Personal = approved user-specific context
Portfolio = created deliverables from this being
```

Named AI Being personality files live in:

```text
personalities/{Name}.md
```

Operating documents live in:

```text
operating-docs/
```

The custom root stays reserved for the local README and top-level folders.

## Runtime Receipts

```text
runtime/
```

Runtime records activation, handoff, deliverable, evidence, hash, and closeout events.

It is the path from static blueprint to automatic timeline.

Rule:

```text
Blueprints explain intended order.
Runtime events prove what actually happened.
```

The current capability surface is tracked in:

```text
runtime/active-capabilities.json
```

Capability states:

```text
available
installed
active
blocked
requires_approval
deprecated
```
