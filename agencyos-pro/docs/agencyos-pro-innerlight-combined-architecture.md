# AgencyOS Pro + InnerLight Combined Architecture

Purpose:

```text
Combine InnerLight and AgencyOS Pro without blurring their responsibilities.
```

Core decision:

```text
AgencyOS Pro owns work routing, permissions, tools, evidence, and closeout.
InnerLight lives inside AgencyOS Pro as the reasoning nervous system.
```

## Product Thesis

AgencyOS Pro is the model-agnostic work body.

InnerLight is the model-agnostic reasoning nervous system inside that body.

Together:

```text
AgencyOS Pro gives the system structure, movement, tools, and authority.
InnerLight gives the system sensation, coherence, signal, and response discipline.
```

Or:

```text
InnerLight helps the system understand the signal.
AgencyOS Pro helps the system move the work.
```

The user experiences one entity:

```text
AgencyOS Pro
```

Inside that entity:

```text
AgencyOS Pro body = operations, routing, tools, evidence, closeout
InnerLight nervous system = signal, coherence, ambiguity, response discipline
Models = replaceable muscles for generation and execution
Human = authority and judgment
```

```text
Human goal
-> AgencyOS Pro scopes the work
-> AgencyOS Pro performs intake
-> InnerLight detects the live signal
-> InnerLight resolves ambiguity and stabilizes reasoning
-> AgencyOS Pro chooses route, agencies, schedule, tools, and permissions

```

## Layer Interaction

| AgencyOS Pro Layer | AgencyOS Pro Owns | InnerLight Contributes |
| --- | --- | --- |
| Scope | Defines what is in, out, urgent, paused, or complete. | Stabilizes against premature expansion. |
| Intake | Captures context, sources, constraints, goals, and human gates. | Detects dominant signal and missing interpretive context. |
| Routing | Assigns agencies, owners, and work paths. | Helps identify domain and signal category. |
| Scheduling | Chooses sequence, priority, parallel work, and pauses. | Supports sequential, parallel, or swarm reasoning mode. |
| Tool Access | Defines available files, apps, APIs, and action surfaces. | Adapters translate model/platform capabilities. |
| Permissions | Decides what can be used in this context. | Safety boundaries help prevent authority drift. |
| Handoffs | Defines output packets and next-owner usability. | Helps reduce ambiguity before handoff. |
| Governance | Defines risk checks, approval rules, and blocked actions. | Safety engine reinforces user authority and boundary discipline. |
| Evidence / Proof | Requires artifact proof, citations, logs, or verification. | Verification suite can check reasoning integrity. |
| State | Tracks active, blocked, waiting, failed, approved, complete, closed. | State/context engine supports runtime and execution state. |
| Memory | Preserves operational decisions and reusable patterns. | Preserves signal continuity without transcript clutter. |
| Observability | Shows what happened, why, what changed, and what evidence exists. | Verification failures can expose reasoning drift. |
| Learning | Updates workflows from results and feedback. | Memory update preserves signal-level learning. |
| Human Gates | Defines when the system must stop and ask. | User authority rule reinforces human control. |
| Recovery | Creates failure packets and next recovery path. | Verification failures can feed recovery diagnosis. |
| Closeout | Labels work as done, monitor, review, template, archive, or no follow-up. | Packaging readiness can support artifact completion checks. |

## AgencyOS Pro Remains The Operational Authority

InnerLight should not replace:

```text
work routing
tool permissions
handoff packet contracts
governance gates
evidence requirements
user-facing audit trail
closeout labels
external action approval
```

AgencyOS Pro should not delegate these to the model or to InnerLight.

These are operating-system responsibilities.

## InnerLight Becomes The Reasoning Nervous System

InnerLight should run inside AgencyOS Pro when the system needs to:

```text
interpret messy human input
separate signal from noise
resolve competing interpretations
stabilize before action
avoid premature advice
generate the smallest valid next move
preserve coherent voice across models
```

InnerLight is especially useful before:

```text
routing
high-stakes recommendation
client-facing framing
reflection or advisory output
conflict resolution
learning-loop interpretation
```

## Model-Agnostic Contract

AgencyOS Pro and InnerLight should remain model-agnostic.

```text
AgencyOS Pro = operating body
InnerLight = reasoning nervous system
Claude / Codex / GPT / Gemini / local model = reasoning engine
Tools = capability surface
Human = authority
Artifacts = work products
Memory = continuity
Governance = trust boundary
```

The model can change.

The operating contract remains stable.

## Example: Client Intake

User asks:

```text
@operator Help me organize a legal spend workflow for invoice review.
```

Combined system flow:

```text
AgencyOS Pro scopes the request as legal spend workflow design.
AgencyOS Pro intakes existing process, tools, approvals, and constraints.
InnerLight detects the signal: adoption of new AI workflow without disrupting current process.
InnerLight stabilizes the reasoning: preserve current workflow first.
AgencyOS Pro routes to Intake, Guidelines, Invoice Review, Risk + Proof, and Reporting.
AgencyOS Pro assigns tool access and permissions.
The model drafts the workflow and prompts.
AgencyOS Pro checks handoffs, evidence, approval gates, and closeout.
Human approves client-facing output.
```

User asks:

Combined system flow:

AgencyOS Pro scopes the work as critical personal income recovery.

AgencyOS Pro routes lanes: cash/housing, voice-over, AgencyOS service outreach, targeted jobs.

## Implementation Rule

Do:

```text
Use InnerLight inside AgencyOS Pro before and during reasoning-heavy steps.
Use AgencyOS Pro for workflow authority, tools, permissions, evidence, and closeout.
Keep human gates explicit.
Keep model adapters replaceable.
```

Do not:

```text
Let InnerLight agents speak directly if nervous-system voice owns final response.
Let the model choose its own permissions.
Let reasoning confidence replace evidence.
Let signal memory replace operational memory.
Let generated output count as closeout without proof.
```
