# Diana Legal Spend Walkthrough: AgencyOS Solo vs AgencyOS Pro

Audience:

```text
Diana, legal spend manager at a law firm.
```

Purpose:

```text
Show how Diana could adopt AgencyOS as a new AI workflow without disrupting the legal spend processes she already has in place.
```

## The Plain-English Idea

AgencyOS Pro is not meant to replace Diana's process or judgment.

It is meant to sit beside her existing workflow, help organize repeatable work, prepare better notes, surface patterns, and make handoffs easier.

InnerLight can support the reasoning layer behind that workflow: it helps the system notice ambiguity, preserve Diana's judgment, and recommend the smallest safe next move.

For legal spend, the goal is simple:

```text
Make invoice review, guideline checks, escalations, reporting, and learning more consistent.
```

## Starting Assumption

Diana already has existing processes for:

```text
invoice review
outside counsel guideline checks
rate and timekeeper review
matter-level context
exceptions and escalations
approval or adjustment notes
reporting
stakeholder communication
```

AgencyOS should not ask her to throw those away.

The right adoption path is:

```text
observe the current workflow
preserve what already works
add AI support beside the workflow
test on a narrow use case
review results
expand only if useful
```

## Intake To Onboarding

This is the most important part.

Before Diana uses AgencyOS Solo or AgencyOS Pro, the system needs enough context to understand how legal spend work currently happens at her firm.

The intake should feel like a short working conversation, not a technical setup.

### Step 1: Understand The Current Workflow

Ask:

```text
How do invoices come in today?
Who reviews them?
What tools or systems are already used?
What guidelines or rules are checked?
What usually causes an exception?
Who approves adjustments or disputes?
What reports are already expected?
```

Why this matters:

```text
AgencyOS needs to support Diana's actual process, not invent a new one in a vacuum.
```

### Step 2: Identify The First Safe Use Case

Ask:

```text
What is one legal spend task that is frequent, structured, and safe to test?
```

Good first candidates:

```text
turning outside counsel guidelines into a review checklist
summarizing invoice review notes
tagging likely billing issues for human review
drafting escalation notes
creating monthly matter spend summaries
tracking repeat exceptions
```

Avoid starting with:

```text
final approval decisions
legal interpretation
disputed client-sensitive decisions
high-stakes policy changes
anything involving confidential data without permission
```

Why this matters:

```text
The first pilot should reduce effort without creating new risk.
```

### Step 3: Define What AI Can And Cannot Do

AgencyOS can help:

```text
organize invoice facts
summarize notes
compare against known guidelines
draft review checklists
prepare escalation language
spot repeat patterns
create reporting drafts
remember approved process patterns
```

AgencyOS should not decide:

```text
whether a disputed invoice is finally approved
whether legal judgment is correct
whether a policy exception should be granted
whether outside counsel relationship issues should be escalated
whether client-sensitive language is final
```

Why this matters:

```text
Diana keeps authority. AgencyOS prepares the work.
```

### Step 4: Confirm The Human Approval Gates

Before onboarding is complete, Diana should name what always comes back to her or another authorized person.

Human approval should be required for:

```text
disputed invoice decisions
policy exceptions
client-specific guideline interpretation
outside counsel relationship concerns
legal, compliance, or confidentiality risk
financial adjustments
final approval notes
external communication
```

Why this matters:

```text
AI workflow adoption is safer when approval gates are clear before work begins.
```

### Step 5: Choose Solo Or Pro For The Pilot

Use AgencyOS Solo if Diana wants:

```text
one AI-supported workflow
quick setup
low overhead
personal productivity support
one repeatable task improved first
```

Use AgencyOS Pro if the firm needs:

```text
multiple legal spend workflows connected
shared guideline memory
matter-level spend visibility
repeat issue tracking
reporting
governance checks
handoffs between reviewers or stakeholders
```

Why this matters:

```text
The adoption path should match the size of the problem.
```

### Step 6: Run A Parallel Pilot

For the first cycle, AgencyOS should run beside the existing process.

The current process remains the source of truth.

AgencyOS produces:

```text
draft checklists
draft summaries
issue tags
suggested escalation notes
reporting drafts
learning notes
```

Diana compares the AI-supported output against the current process.

Why this matters:

```text
The firm can test value without risking disruption.
```

### Step 7: Review The Pilot

After the first test, ask:

```text
Did this save time?
Did it improve consistency?
Did it make handoffs clearer?
Did it surface repeat issues?
Did it create any risk?
Should we continue, revise, expand, or stop?
```

Why this matters:

```text
Adoption should be earned by usefulness, not assumed because the technology is new.
```

## Use Case 1: Diana Uses AgencyOS Solo

Scenario:

```text
Diana wants one AI workflow to help with invoice review against outside counsel guidelines.
```

Best fit:

```text
Solo is the right fit when Diana wants to test AgencyOS personally before introducing a broader legal spend operating system.
```

### What Diana Gives The System

```text
sample outside counsel guidelines
invoice review checklist or current process notes
common billing issues
example adjustment reasons
preferred summary format
approval rules
what should never be automated
```

### What AgencyOS Solo Does

AgencyOS Solo creates one focused legal spend review agency.

It helps Diana:

```text
turn guidelines into a checklist
review invoice notes against that checklist
flag possible issues for human review
draft adjustment or escalation notes
summarize repeat issues
save what was learned for next time
```

### What Diana Still Owns

Diana still owns:

```text
final judgment
approval or dispute decisions
policy interpretation
client-sensitive communication
relationship-sensitive escalation
financial adjustment approval
```

### Solo Walkthrough

1. Diana gives AgencyOS one workflow: invoice review against guidelines.
2. AgencyOS asks only for the materials needed for that workflow.
3. AgencyOS creates a review checklist.
4. Diana tests it on a sample or low-risk invoice.
5. AgencyOS drafts issue tags and review notes.
6. Diana approves, edits, or rejects the suggestions.
7. AgencyOS saves repeat patterns for future review.
8. Diana decides whether the workflow is useful enough to keep.

### Example Solo Output

```text
invoice review checklist
possible billing issue tags
draft escalation note
summary of guideline concerns
repeat issue log
human approval checklist
```

### Solo Value

```text
Faster first draft.
Cleaner review notes.
Less repetitive checklist work.
Better personal consistency.
Low-risk way to try AI in the workflow.
```

### Solo Limitation

Solo helps one workflow at a time.

It may become too limited when Diana needs to connect:

```text
multiple matters
multiple reviewers
multiple client guidelines
dispute history
reporting
training patterns
institutional memory
```

## Use Case 2: Diana Uses AgencyOS Pro

Scenario:

```text
Diana wants a broader AI workflow that supports legal spend management across invoices, matters, guidelines, reporting, risk, and learning.
```

Best fit:

```text
Pro is the right fit when legal spend work is not just one task, but a repeatable operating system across matters and stakeholders.
```

### What Diana Gives The System

```text
current invoice intake process
review roles and responsibilities
outside counsel guideline sources
common exception types
matter reporting needs
approval and escalation rules
existing templates
confidentiality boundaries
what must remain human-approved
```

### What AgencyOS Pro Creates

AgencyOS Pro separates the work into coordinated agencies:

```text
Matter Spend
Invoice Review
Guidelines
Reporting
Risk + Proof
Insights
```

Each agency has a clear role.

Matter Spend:

```text
Tracks matter budgets, client preferences, spend patterns, and open disputes.
```

Invoice Review:

```text
Checks invoices, rates, timekeeper issues, billing descriptions, and adjustment notes.
```

Guidelines:

```text
Maintains outside counsel guidelines, rate rules, exception precedents, and approved review language.
```

Reporting:

```text
Turns review activity into matter summaries, dispute logs, and spend trend reports.
```

Risk + Proof:

```text
Checks whether decisions have evidence, approval notes, and the right escalation path.
```

Insights:

```text
Finds repeat issues, training gaps, reviewer inconsistency, and process improvements.
```

### Pro Walkthrough

1. Diana maps the existing legal spend process.
2. AgencyOS Pro identifies which parts should become separate agencies.
3. Each agency gets a clear responsibility.
4. Intake captures invoice, matter, guideline, and approval context.
5. Invoice Review checks the invoice.
6. Guidelines checks the applicable rules.
7. Risk + Proof flags anything that needs evidence or human approval.
8. Reporting drafts matter and spend summaries.
9. Insights identifies repeat patterns.
10. Diana reviews exceptions and final decisions.
11. The system saves approved patterns for future use.

### Example Pro Output

```text
matter spend dashboard outline
invoice review checklist
outside counsel guideline library
exception and dispute log
approval gate map
audit note template
monthly reporting summary
repeat issue report
training gap notes
process improvement recommendations
```

### Pro Value

```text
More consistent invoice review.
Better matter-level visibility.
Clearer escalation paths.
Reusable guideline memory.
Stronger audit trail.
Better reporting.
Less knowledge loss after an invoice closes.
```

### Pro Limitation

Pro takes more setup than Solo.

It is worth it when the workflow has enough volume, complexity, or risk to justify a coordinated system.

## Adoption Path

Recommended path for Diana:

```text
Start with Solo for one safe workflow.
Use the results to see where the process gains value.
Move to Pro only if the work needs coordination, shared memory, reporting, or governance.
```

This keeps the adoption simple:

```text
try
learn
expand only where useful
```

## What Success Looks Like

After the first pilot, success should look like:

```text
Diana spends less time recreating the same review steps.
Invoice notes are clearer.
Exceptions are easier to explain.
Repeat issues are easier to spot.
Handoffs are cleaner.
Reports are easier to draft.
Human approval stays protected.
```

## What AgencyOS Should Not Do

AgencyOS should not:

```text
replace Diana's legal spend judgment
override firm policy
make final disputed invoice decisions
send external messages without approval
store sensitive information without permission
change existing workflows without review
create legal, financial, or client-facing commitments on its own
```

## Final Takeaway

AgencyOS Solo is the easiest way for Diana to try AI on one legal spend workflow.

AgencyOS Pro is the stronger fit when the firm wants legal spend review to become a coordinated, governed, repeatable operating system.

The safest adoption path is not to replace the current process.

It is to run AgencyOS beside the current process, prove value, then expand only where it clearly helps.
