# Generic Effortless Intake Questions

Use this when onboarding should feel light, friendly, and practical while still capturing the critical inputs AgencyOS needs to route work.

Design rule:

```text
Ask only what changes routing, risk, handoffs, approval, evidence, or the next useful action.
Let the system infer the rest.
```

Suggested intro:

```text
Answer what you know. Short answers are fine. If something is unclear, say "not sure" and the system will route it as a research task or decision point.
```

## Quick Start

1. What are you trying to make happen?

2. What would be a useful first win?

3. Who is this for?
   - Me
   - My team
   - A client
   - Customers/users
   - A partner
   - Not sure yet
   - Other

4. What kind of help do you want from the system?
   - Think through the problem
   - Research options
   - Build or draft something
   - Organize a workflow
   - Create sales/marketing assets
   - Review risk or claims
   - Track progress and learning
   - Not sure yet

## Context

5. What is already true today?

6. What changed recently, or why does this matter now?

7. What have you already tried?

8. What existing materials should the system use?
   - Website
   - Notes
   - Documents
   - Spreadsheet
   - Deck
   - Code/repo
   - Customer feedback
   - Prior decisions
   - Nothing yet
   - Other

9. Paste any useful links, files, or source notes.

## Outcome

10. What should exist at the end of this first pass?
    - Plan
    - Research brief
    - Decision memo
    - Workflow
    - Prompt set
    - Content draft
    - Sales asset
    - Prototype
    - Tracker
    - Presentation
    - Other

11. How polished does the first version need to be?
    - Rough internal draft
    - Clear working version
    - Client-ready
    - Public-ready
    - Not sure yet

12. What does "done enough" look like?

13. Is there a deadline or useful review date?

## Scope

14. What should be included?

15. What should be left out for now?

16. What should the system avoid doing?

17. Which path feels most important right now?
    - Fastest useful output
    - Best quality
    - Lowest cost
    - Lowest risk
    - Best learning
    - Best chance of revenue
    - Best long-term foundation

## People And Authority

18. Who gets to make the final decision?

19. Who else needs to be consulted or informed?

20. What can the system do without asking first?
    - Research
    - Draft
    - Organize files
    - Suggest next steps
    - Create templates
    - Compare options
    - Update internal docs
    - Nothing without asking
    - Other

21. What should always come back to a human first?
    - Publishing
    - Sending messages
    - Pricing
    - Spending money
    - Making promises
    - Legal/compliance judgment
    - Brand/positioning changes
    - High-risk recommendation
    - Other

## Risk And Truth

22. What would be bad if the system got it wrong?

23. Are there claims, facts, or promises that must be verified?

24. What language or assumptions should the system avoid?

25. How cautious should the system be?
    - Light: low-stakes, easy to revise
    - Standard: visible to others or affects work
    - Strict: money, trust, legal, safety, privacy, or reputation involved
    - Not sure

26. What sources should be treated as trusted?

27. What sources should not be trusted without review?

## Workflow

28. What should happen automatically after the first output is ready?
    - Send to another agency/workstream
    - Create follow-up tasks
    - Start research
    - Start drafting
    - Start review
    - Wait for human approval
    - Not sure yet

29. Where should the system pause?
    - Missing information
    - Conflicting recommendations
    - Risky claim
    - Public-facing output
    - Budget or resource decision
    - Final approval
    - Continue/revise/stop decision

30. What should be tracked as work moves forward?
    - Decisions
    - Open questions
    - Evidence
    - Tasks
    - Owners
    - Handoffs
    - Risks
    - Feedback
    - Results

31. How often should the system review progress?
    - After each task
    - Daily
    - Weekly
    - Monthly
    - After feedback arrives
    - Only when asked

## Learning Loop

32. What feedback would tell us this is working?

33. What feedback would tell us to revise?

34. What feedback would tell us to stop?

35. What should the system learn from this work so the next pass is easier?

## Final Check

36. Is there anything personal, political, sensitive, confidential, or high-stakes the system should know before starting?

37. If the system only did one useful thing next, what should it be?

38. Is there anything you are unsure about that you want the system to help clarify?

## Optional Short Version

Use this when the user is busy or overwhelmed:

```text
1. What are you trying to make happen?
2. What would be a useful first win?
3. Who is this for?
4. What exists already?
5. What should be avoided?
6. Who decides?
7. What needs human approval?
8. What would be bad if wrong?
9. What should happen next automatically?
10. Where should the system pause?
```
