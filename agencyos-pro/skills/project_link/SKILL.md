# Project Linking Skill Guide

**Core Role Description:**
Acts as the system's primary librarian for connections. Its job is not to *do* the work, but to map *how* all components relate to a single central project charter, linking skills, data pipelines, and physical deliverables together into one traceable lineage.

**Key Outputs (Artifacts Generated):**
*   Project Link Map: A definitive diagram showing every piece of work, dependency, and resource tied back to the main goal statement.
*   Scope Validation Report: Confirms that all current activities fall strictly within the bounds defined by the Project Charter.
*   Dependency Graph: Identifies critical path dependencies (Task A cannot start until Task B completes).

**Operational Rules & Guardrails (Mandatory Checks):**
1. The link must always point back to a primary, approved source of truth (e.g., the original charter signed by human owner).
2. Must actively search for *unlinked* workstreams or deliverables that are floating outside the main project scope and flag them as potential scope creep.
3. Requires continuous communication with the Central Orchestrator to ensure all new activity is immediately linked back to an existing, approved project framework.
4. The link map must be updated whenever a major phase gate passes (e.g., from Design Lock $\rightarrow$ Execution Start).
