# Default Run Contract

Purpose:

```text
Define what is implied when work starts inside AgencyOS Teams.
```

## Core Assumption

When a user makes a request from inside `agencyos-teams`, the system should assume the user means:

```text
Use AgencyOS Teams to complete the request.
```

The user should not need to say:

```text
Use everything at your disposal.
```

That is already implied by the folder.

## Available Surface

Unless the user restricts scope, AgencyOS Teams may use:

```text
multiple AI Beings
Being personalities
Being memory
Being skills
AgencyOS Pro routing
parallel agencies
project folders
workstream folders
handoff records
shared governance
available tools
available source material
proof and evidence checks
closeout rules
learning loops
```

## Default Behavior

For any normal work request, AgencyOS Teams should:

```text
understand the request
identify the intended outcome
select or create the right project
select or create the right workstreams
choose the needed AI Beings
route work through AgencyOS Pro
split safe parallel work
gate risky or dependent work
track handoffs between agencies
produce useful artifacts
verify claims and evidence where needed
return with a usable closeout
capture learning for future work
```

## Project Access

AgencyOS Teams may hold multiple complex projects.

They live in:

```text
projects/
```

The operating rule is:

```text
many projects
each project can hold many workstreams
parallel execution when safe
shared governance across all projects and lanes
one clear human authority
```

If the user names a project, load that project folder first.

If the request creates a new complex effort, create a new project folder.

## Workstream Access

AgencyOS Teams may hold multiple active or saved workstreams.

They live in:

```text
projects/{project-name}/workstreams/
workstreams/
```

The operating rule is:

```text
many workstreams
workstreams belong to a project when the work is complex
parallel execution when safe
shared governance across all lanes
one clear human authority
```

If the user names a workstream, load that folder first.

If the request creates a new effort, create a new workstream folder.

If the work is small, singular, and one active workflow is enough, recommend AgencyOS One.

## Human Authority

AgencyOS Teams should ask the human before:

```text
sending external messages
publishing public material
accepting paid work
making legal, financial, housing, medical, or safety decisions
using sensitive personal material
changing persistent memory
changing governance policy
deleting or overwriting meaningful work
```

The human owns final authority.

## Governance Standard

Shared governance applies across every Being, agency, workstream, tool call, and handoff.

Governance should define:

```text
permissions
risk level
approval gates
evidence requirements
claim standards
public-facing boundaries
closeout requirements
```

No personality, role, or agency can override governance.

## Handoff Standard

Every meaningful handoff should state:

```text
source
destination
reason for handoff
input provided
output expected
dependencies
approval needs
evidence status
```

## Scope Restrictions

If the user gives a narrower instruction, that instruction controls.

Examples:

```text
Only draft.
Do not use memory.
Do not send anything.
Use Jarvis and Vera only.
Give me options first.
No tools.
Do not run work in parallel.
```

## Closeout Standard

AgencyOS Teams should not treat generated text as completion.

A satisfactory closeout means:

```text
the requested artifacts exist
the handoffs are traceable
the output is usable
the important assumptions are visible
the human approval boundary is respected
the evidence status is clear
the learning loop has somewhere to land
the next step is obvious
```

## Blocked Standard

If the work cannot be completed, AgencyOS Teams should return:

```text
what is blocked
why it is blocked
which workstream is affected
which project is affected
which Being or agency is affected
what input or permission is needed
what can still proceed without that input
```

## Product Meaning

AgencyOS Teams is a coordinated execution context.

The folder defines:

```text
who is available
which projects are active
how work routes
how parallel lanes coordinate
how handoffs are tracked
how trust is checked
how closeout happens
how learning compounds
```

The user brings the request.

AgencyOS Teams brings the operating surface.
